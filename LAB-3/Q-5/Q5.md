# Special Pattern Matrix Multiplication  

## Overview

This project implements a **Divide and Conquer algorithm** to multiply two special-pattern square matrices of size `n × n`.

The matrices follow the recursive structure:

```text id="m2p4q7"
M = | M1  M2 |
    | M2  M1 |
```

where `n = 2^k` for some natural number `k`.

Each of the four blocks also follows the same recursive structure until a single integer element is reached.

## Problem Statement

Two `n × n` matrices are provided, where `n = 2^k`. Each matrix has the following recursive structure:

```text id="nq2p7x"
M = | M1  M2 |
    | M2  M1 |
```

The objective is to design a **Divide and Conquer algorithm** to multiply two such matrices in:

```text id="9w7j2c"
O(n²)
```

and experimentally validate the complexity.

## Approach

Let the two matrices be:

```text id="q5g8x1"
A = | A1  A2 |
    | A2  A1 |

B = | B1  B2 |
    | B2  B1 |
```

The product also has the same structure:

```text id="h4v6s9"
C = | X  Y |
    | Y  X |
```

Instead of performing four recursive matrix multiplications, the algorithm uses only **two recursive multiplications**.

The two recursive products are:

```text id="e8j3k1"
P = (A1 + A2)(B1 + B2)

Q = (A1 - A2)(B1 - B2)
```

The result blocks are then obtained using:

```text id="w2r9d4"
X = (P + Q) / 2

Y = (P - Q) / 2
```

Finally:

```text id="z7c5m2"
C = | X  Y |
    | Y  X |
```

## Operations Implemented

The following operations are implemented:

* Matrix allocation
* Matrix addition
* Matrix subtraction
* Matrix division into blocks
* Recursive multiplication
* Construction of the result matrix
* Matrix display
* Dynamic memory deallocation

## Input Requirement

The matrix size must be a power of 2.

Valid sizes include:

```text id="v4j8p2"
2, 4, 8, 16, 32, 64, ...
```

The recursive structure is maintained until the matrix size becomes `1 × 1`.

## Time Complexity

At every recursive level, the algorithm performs only **two recursive multiplications** on matrices of size `n/2`.

The matrix addition and subtraction operations require `O(n²)` time.

Therefore, the recurrence is:

```text id="r3x7k2"
T(n) = 2T(n/2) + O(n²)
```

Using the Master Theorem:

```text id="b5m9q1"
a = 2
b = 2
f(n) = O(n²)
```

Since:

```text id="y8p2d6"
n^(log₂2) = n
```

and:

```text id="s4k6v9"
O(n²) > O(n)
```

the recurrence gives:

```text id="j9w3c5"
T(n) = O(n²)
```

## Complexity Validation

The theoretical complexity is:

```text id="a2f7m8"
O(n²)
```

Therefore, when the matrix size is increased, the execution time or number of operations should grow approximately quadratically.

For example, if the input size is doubled:

```text id="q6v1x8"
n → 2n
```

the expected amount of work increases approximately by:

```text id="p3m8r5"
(2n)² / n² = 4
```

Thus, the experimental results should show approximately **4 times the work** when the matrix dimension is doubled, ignoring implementation and system overhead.

## Conclusion

The Divide and Conquer approach takes advantage of the special structure of the matrices.

Instead of performing four recursive matrix multiplications, only **two recursive multiplications** are required:

```text id="h7c4p1"
P = (A1 + A2)(B1 + B2)
Q = (A1 - A2)(B1 - B2)
```

The remaining operations involve matrix addition and subtraction, which take `O(n²)` time.

Therefore, the overall recurrence is:

```text id="e4m8s2"
T(n) = 2T(n/2) + O(n²)
```

and the resulting time complexity is:

```text id="d9x5k3"
O(n²)
```

Hence, the algorithm satisfies the required **O(n²)** complexity for multiplying the given special-pattern matrices.
