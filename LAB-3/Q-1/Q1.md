# Binary vs Ternary Search

## Overview

This project implements **Binary Search** and **Ternary Search** for searching an element in a sorted array and experimentally compares their performance.

### Searching Algorithms

1. Binary Search
2. Ternary Search

Binary Search divides the search space into two nearly equal parts, while Ternary Search divides it into three nearly equal parts.

## Operations Implemented

The following searching operations are implemented:

* Binary Search
* Ternary Search

The program searches for a given element `x` in a sorted array and returns its position if the element is found.

## Experimental Analysis

The program tests different input sizes:

```text
5000, 10000, 15000, ..., 100000
```

For each input size, the number of comparisons performed by Binary Search and Ternary Search is recorded.

## Performance Measurement

The number of comparisons is used as the primary performance metric.

```text
X-axis → Input Size (n)
Y-axis → Number of Comparisons
```

The results can be used to generate a graph comparing Binary Search and Ternary Search.

## Expected Result

Although Ternary Search divides the array into three parts, it requires more comparisons at each level because it checks two middle elements.

Binary Search generally performs fewer comparisons and is therefore expected to be more efficient than Ternary Search.

## Time Complexity

| Algorithm      | Best Case | Average Case | Worst Case |
| -------------- | --------- | ------------ | ---------- |
| Binary Search  | O(1)      | O(log₂ n)    | O(log₂ n)  |
| Ternary Search | O(1)      | O(log₃ n)    | O(log₃ n)  |

## Conclusion

The experimental analysis demonstrates that **Binary Search is generally better than Ternary Search** in terms of the number of comparisons, despite Ternary Search reducing the search space into three parts.

Both algorithms require a **sorted array** and use the **Divide and Conquer** technique.
