# Selection Sort and Loop Invariants

## Overview

This project implements **Selection Sort** and uses the concept of **loop invariants** to prove the correctness of the sorting algorithm.

The algorithm repeatedly finds the smallest element from the unsorted portion of the array and places it at the correct position.

## Problem Statement

Given an array `A[1...n]`, Selection Sort works as follows:

1. Find the smallest element in `A[1...n]` and exchange it with `A[1]`.
2. Find the smallest element in `A[2...n]` and exchange it with `A[2]`.
3. Continue this process until the first `n - 1` elements are correctly placed.
4. Implement the algorithm in C and validate its correctness and running time.

## Algorithm

For every position `i` from `0` to `n-2`:

1. Assume `A[i]` is the minimum element.
2. Search the remaining unsorted portion `A[i+1...n-1]`.
3. Find the index of the smallest element.
4. Exchange it with `A[i]`.
5. Continue until the array is sorted.

## Pseudocode

```text id="r8k2m4"
SelectionSort(A, n)

for i = 1 to n - 1
    min_index = i

    for j = i + 1 to n
        if A[j] < A[min_index]
            min_index = j

    exchange A[i] with A[min_index]
```

## Loop Invariant

### Invariant

At the beginning of each iteration of the outer loop with index `i`:

> The subarray `A[1...i-1]` contains the smallest `i-1` elements of the array in sorted order.

In other words:

```text id="x6p3v9"
A[1] ≤ A[2] ≤ ... ≤ A[i-1]
```

and every element in this portion is smaller than or equal to every element in the remaining unsorted portion.

### Initialization

Before the first iteration, `i = 1`.

The sorted portion `A[1...0]` is empty, so the loop invariant is true.

### Maintenance

During each iteration, the algorithm finds the smallest element in the unsorted portion `A[i...n]` and exchanges it with `A[i]`.

Therefore, `A[i]` becomes the smallest element of the remaining unsorted portion.

The sorted portion is increased by one element, so the loop invariant remains true.

### Termination

When the loop terminates after `i = n-1`, the first `n-1` elements are in sorted order.

The remaining element `A[n]` must automatically be the largest element.

Therefore, the entire array is sorted.

## Why Only n-1 Iterations?

The algorithm needs to run only for the first `n-1` elements because after placing the smallest `n-1` elements in their correct positions, only one element remains.

That final element must already be in its correct position.

Therefore, performing another iteration for the last element is unnecessary.

## Time Complexity

The number of comparisons performed by Selection Sort is independent of the initial order of the array.

The number of comparisons is:

```text id="f3k7w2"
(n-1) + (n-2) + ... + 2 + 1
```

Therefore:

```text id="p9d4x6"
n(n-1)/2
```

Hence, the running time is:

```text id="z2m8q5"
Θ(n²)
```

### Worst Case

```text id="j7c3v1"
Θ(n²)
```

### Best Case

```text id="k5r9s4"
Θ(n²)
```

The best-case running time is **not better** because Selection Sort still scans the entire unsorted portion to find the minimum, even when the array is already sorted.

## Conclusion

Selection Sort maintains a loop invariant stating that the portion before the current index contains the smallest elements in sorted order.

The invariant is established through:

* **Initialization**
* **Maintenance**
* **Termination**

The algorithm requires only `n-1` iterations because the final element is automatically placed correctly.

Selection Sort performs `n(n-1)/2` comparisons regardless of the input arrangement. Therefore, its:

```text id="m6p1q8"
Best Case    = Θ(n²)
Average Case = Θ(n²)
Worst Case   = Θ(n²)
```

The experimental analysis validates the theoretical running-time claim.
