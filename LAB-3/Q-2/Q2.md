# Search the Defective Coin

## Overview

This project implements a **Divide and Conquer algorithm** to find a possible defective coin that is lighter than the other coins using a balance weighing scale.

The algorithm determines whether a lighter defective coin exists and identifies its position, or reports that all coins have identical weight.

### Problem

There are `n` coins where:

* All normal coins have the same weight.
* At most one coin may be defective.
* The defective coin, if present, can only be **lighter** than the normal coins.
* The defective coin may also not exist.
* A balance scale is used to compare the total weight of two groups of coins.

## Algorithm

The candidate coins are divided into **three nearly equal groups**.

1. Divide the candidate coins into three groups.
2. Weigh the first group against the second group.
3. If the first group is lighter, the defective coin is in the first group.
4. If the second group is lighter, the defective coin is in the second group.
5. If both groups have equal weight, both groups are normal and the defective coin, if present, must be in the third group.
6. Recursively repeat the process on the selected group.
7. When only one candidate remains, determine whether it is defective.
8. Report the defective coin or conclude that no defective coin exists.

## Operations Implemented

The following operations are implemented:

* Divide the coins into three groups
* Compare two groups using a balance scale
* Recursively search for the defective coin
* Identify the lighter coin
* Verify whether a defective coin exists

The program uses a `weigh()` function to compare the total weights of two groups.

## Experimental Analysis

The program can be tested with different input sizes:

```text
1000, 2000, 3000, ..., 10000
```

For each input size, the number of balance-scale comparisons can be recorded.

## Performance Measurement

The primary performance metric is the **number of balance-scale comparisons**.

```text
X-axis → Number of Coins (n)
Y-axis → Number of Comparisons
```

The recorded values can be used to generate a graph showing the relationship between the number of coins and the number of comparisons.

## Time Complexity

At every step, the candidate set is reduced to approximately one-third.

Therefore, the recurrence is:

```text
T(n) = T(n/3) + O(1)
```

Hence:

```text
T(n) = O(log₃ n)
```

The number of balance-scale comparisons grows logarithmically with the number of coins.

## Expected Result

As the number of coins increases, the number of balance-scale comparisons increases logarithmically.

The algorithm efficiently reduces the search space at every step and identifies the possible defective coin without checking every coin individually.

## Conclusion

The Divide and Conquer approach efficiently finds a lighter defective coin, if one exists, using a balance weighing scale.

By dividing the candidate coins into three groups at each step, the search space is significantly reduced after every weighing.

The experimental analysis demonstrates that the number of comparisons grows logarithmically with the input size.

**Time Complexity: O(log₃ n)**
