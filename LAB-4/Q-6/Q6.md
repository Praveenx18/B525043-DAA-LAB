# Maximum Interval Overlap

## Problem

Given a set of `n` intervals `(l, r)`, find a point `p` that lies in the maximum number of intervals.

An endpoint is considered to be part of its interval.

## Approach

Represent each interval using two events:

- Left endpoint → `+1`
- Right endpoint → `-1`

Sort all `2n` events by position using Merge Sort.

If two events have the same position, process the left endpoint before the right endpoint because endpoints are included in the intervals.

Then scan the events from left to right:

- Start event: increment the current count.
- End event: decrement the current count.
- If the current count is greater than the maximum, store the current position as the best point.

## Example

Input:

`(10,40), (20,60), (50,90), (15,70)`

Output can be:

`p = 20, maximum overlap = 3`

Other points such as `50` are also valid.

## Complexity

- Number of events: `2n`
- Sorting: **O(n log n)**
- Sweep: **O(n)**
- Overall Time Complexity: **O(n log n)**
- Space Complexity: **O(n)**

## Validation

The C program counts comparisons and measures execution time for different input sizes to validate the theoretical **O(n log n)** complexity.
